# FPPG Calculation System - Technical Guide

## Overview

This document explains how Fantasy Points Per Game (FPPG) are calculated in the system and documents a critical bug that was fixed on 2025-11-13.

## System Architecture

### Data Sources

The application uses multiple data sources for player statistics:

1. **`server/data/stats.json`** - Cached stats from NHL API
   - Contains comprehensive, up-to-date player statistics
   - Generated by the hydration script (`apps/api` hydration)
   - Player IDs use format: `"nhl:8478427"` (with prefix)
   - Updated periodically (should be kept fresh)

2. **`server/data/coach/users/{userId}/roster.json`** - User roster data
   - Contains basic player info and slot assignments
   - Player IDs use format: `"nhl:8478427"` (with prefix)
   - May contain stale `games_played` and `stats` values
   - Should NOT be used as source of truth for stats

3. **`server/data/players.json`** - Player directory
   - Master list of all NHL players
   - Used for player lookups and metadata

## How FPPG Calculation Works

### Endpoints

1. **`GET /api/coach/users/:userId/roster`**
   - Returns roster with FPPG calculated using `buildRosterPlayerResponse()`
   - Correctly uses `statsContext` for all stats
   - Path: `server/src/routes/coach.ts:buildRosterPlayerResponse()`

2. **`POST /api/coach/users/:userId/projections`**
   - Returns projections including FPPG for each player
   - Uses `buildProjection()` → `calculatePlayerFppg()`
   - Path: `server/src/features/coach/scoring.ts`

### Calculation Flow

```
Player Request
    ↓
resolvePlayerForProjection() - Loads player from roster.json
    ↓
buildProjection() - Creates projection
    ↓
calculatePlayerFppg() - Calculates FPPG
    ↓
calculateSkaterFppg() or calculateGoalieFppg()
    ↓
statsContext.players.get(playerId) - CRITICAL: ID format must match!
    ↓
Fallback to player.games_played if stats not found (BAD!)
```

## The Bug (Fixed 2025-11-13)

### Symptom

- FPPG values were stale and didn't update
- Sebastian Aho showed 1.69 FPPG instead of 1.94
- Cutter Gauthier showed 2.07 FPPG instead of 2.54
- Values matched week-old data from roster.json

### Root Cause

**Player ID Format Mismatch:**

1. `stats.json` uses keys with prefix: `"nhl:8478427"`
2. `resolvePlayerForProjection()` normalizes IDs to numeric: `"8478427"`
3. `calculateSkaterFppg()` did lookup: `statsContext.players.get("8478427")`
4. Lookup returned `undefined` because key didn't match
5. Code fell back to stale `player.games_played` from roster.json

### The Fix

**File:** `server/src/features/coach/scoring.ts`

**Before:**
```typescript
const record = statsContext?.players.get(player.id)?.skaterStats;
```

**After:**
```typescript
// Try both ID formats: numeric-only and with "nhl:" prefix
const record = statsContext?.players.get(player.id)?.skaterStats ||
               statsContext?.players.get(`nhl:${player.id}`)?.skaterStats;
```

This change was applied to both:
- `calculateSkaterFppg()` (line ~108)
- `calculateGoalieFppg()` (line ~156)

## Why This Happened

### Contributing Factors

1. **Inconsistent ID Formats**
   - Different parts of the system use different ID formats
   - No single source of truth for ID normalization

2. **Silent Failures**
   - Map.get() returns undefined on miss (no error thrown)
   - Fallback to roster.json data seemed reasonable but was incorrect

3. **Multiple Data Sources**
   - Having both roster.json and stats.json created confusion
   - roster.json should ONLY be for slot assignments, not stats

4. **Browser Caching**
   - Initial debugging focused on browser/API caching
   - Real issue was deeper in the calculation logic

5. **Vite Proxy Misconfiguration**
   - Frontend was proxying to wrong port (8081 vs 8080)
   - This masked the real issue temporarily

## Prevention Guidelines

### 1. ID Format Consistency

**ALWAYS use the fallback pattern when looking up from statsContext:**

```typescript
// Good
const record = statsContext?.players.get(player.id)?.skaterStats ||
               statsContext?.players.get(`nhl:${player.id}`)?.skaterStats;

// Bad
const record = statsContext?.players.get(player.id)?.skaterStats;
```

### 2. Data Source Priority

**For calculating FPPG, ALWAYS prioritize in this order:**

1. `statsContext` (from stats.json) - CURRENT, COMPLETE DATA
2. Player object fallback - ONLY as last resort for missing data

**NEVER use roster.json as primary source for statistics.**

### 3. Stats Cache Freshness

The `stats.json` file should be kept up-to-date:

```bash
cd apps/api
npm run hydrate
```

This fetches fresh data from NHL API and updates the cache.

### 4. Server Restart After Updates

After updating stats cache, restart the server to reload the in-memory statsContext:

```bash
cd server
npm run build
npm start
```

### 5. Port Configuration

Ensure Vite proxy points to correct backend port:

**File:** `web/vite.config.ts`
```typescript
proxy: {
  '/api': {
    target: 'http://localhost:8080',  // Must match server port
    changeOrigin: true,
    secure: false,
  },
}
```

## Common Issues & Solutions

### Issue: FPPG values are stale

**Symptoms:**
- FPPG hasn't changed in days
- Values don't match current season stats

**Diagnosis:**
1. Check if stats.json is up-to-date: `ls -lh server/data/stats.json`
2. Check server logs for stats cache loading
3. Test API endpoints directly with curl

**Solution:**
1. Run hydration: `cd apps/api && npm run hydrate`
2. Restart server: `cd server && npm start`
3. Hard refresh browser

### Issue: API returns correct values but UI shows old values

**Symptoms:**
- curl shows correct FPPG
- Browser shows old FPPG

**Solution:**
1. Check Vite proxy configuration (port 8080)
2. Restart Vite dev server
3. Hard refresh browser (Ctrl+Shift+R)
4. Clear browser site data if necessary

### Issue: statsContext lookup returns undefined

**Symptoms:**
- FPPG calculations fall back to roster.json
- Server logs show stats cache loaded correctly

**Solution:**
- Verify ID format handling in scoring.ts
- Ensure fallback pattern is used: `get(id) || get('nhl:' + id)`
